# Chicago 311 Response Times Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load Chicago's 311 Service Requests (2023 onward) into PostgreSQL incrementally, expose analysis views and query files for dashboards and findings, and test it all with pytest (pipeline + SQL, with coverage) and Playwright TypeScript (contract and UI tests against the Chicago Data Portal), running in GitHub Actions.

**Architecture:** A small Python package `pipeline/` pages through the Socrata API with keyset pagination on `(:updated_at, :id)`, upserts into `raw.service_requests`, and records a watermark in `meta.load_state` in the same transaction. Plain SQL files under `sql/` define tables (`sql/schema/`), analysis views in schema `mart` (`sql/views/`), and finding queries (`sql/analysis/`). An export command writes the aggregated views to CSV for Tableau Public; Power BI imports the same views directly. A separate `e2e/` Playwright TypeScript project tests the live portal.

**Tech Stack:** Python 3.12, PostgreSQL 16 (Docker), psycopg 3, requests, pytest, pytest-cov, responses, ruff; Node 20 (CI) / Node 18+ (local), `@playwright/test` 1.48.2, TypeScript 5.6; GitHub Actions; Codecov.

**Spec:** `docs/superpowers/specs/2026-10-31-chicago-311-design.md`

## Global Constraints

- Data scope: only requests with `created_date >= '2023-01-01'`.
- Source dataset: `https://data.cityofchicago.org/resource/v6vf-nfxy.json`; community areas: `https://data.cityofchicago.org/resource/igwz-8jzy.json`.
- Incremental watermark: the pair (`:updated_at`, `:id`) stored as the exact text the API returned, in `meta.load_state`. It advances only in the same transaction as the page's upsert.
- Retries: HTTP 429, 5xx, connection errors and timeouts retry with exponential backoff (sleeps 1, 2, 4, 8 seconds), failing after 5 attempts. Other 4xx fail immediately.
- Socrata floating timestamps (`created_date`, `closed_date`, `last_modified_date`) are stored as `timestamp without time zone` and are America/Chicago local time. `:updated_at` is stored as `timestamptz`.
- Cleaning rules (in `mart.v_requests_clean`): exclude `duplicate = true`; exclude `sr_type = '311 INFORMATION ONLY CALL'`; `response_hours` only for `status = 'Completed'`; completed rows with a null or earlier-than-created `closed_date` are excluded from metrics and listed in `mart.v_data_issues`.
- Geography: community area (77 areas) is the primary geography; ward is kept but not used for comparisons.
- Percentiles use `percentile_cont`.
- Backlog age bucket labels, exactly: `1: <1 day`, `2: 1-7 days`, `3: 7-30 days`, `4: 30-90 days`, `5: 90+ days`.
- Coverage: `pytest --cov` on `pipeline/`, CI fails under 85%.
- Playwright: 2 retries in CI, trace on first retry, HTML report uploaded as an artifact; live API queries use `$limit` of 20 or less.
- Code comments, docs and commit messages are plain, normal English.
- Out of scope: forecasting, dbt, cloud-hosted Postgres, real-time updates.

## Decisions made while planning (refinements of the spec)

- **Compound watermark.** The spec names `:updated_at` as the watermark. Live checks showed thousands of rows share one `:updated_at` value (batch publishes), so the watermark is the pair (`:updated_at`, `:id`) and paging uses `$order=:updated_at,:id` with a keyset `$where`. Checked live on 2026-11-01: the keyset query works, and a malformed `$where` returns HTTP 400.
- **Community area names.** A `ref.community_areas` table (loaded from dataset `igwz-8jzy`, 77 rows, fields `area_numbe` and `community`) gives views readable area names. Supports the spec's goal of learning the city's geography.
- **`mart.v_city_month`.** Added a citywide monthly view for the dashboard overview page; the spec's per-type views cannot produce a citywide median.
- **Views are rebuilt each migration.** `apply_migrations` drops and recreates schema `mart` before running `sql/views/*.sql`, so a changed column list never blocks `CREATE OR REPLACE VIEW`.
- **Known data behavior (document, don't fix):** no row had `:updated_at` before 2026-01-01 when checked, meaning the portal re-publishes the whole dataset at times. When that happens, the next incremental run refetches everything. The upsert is idempotent, so this is slow but correct.

`pipeline/migrate.py`:

```python
"""Apply the SQL files under sql/ in filename order."""

from pathlib import Path

import psycopg

SQL_ROOT = Path(__file__).resolve().parent.parent / "sql"


def apply_migrations(conn: psycopg.Connection, sql_root: Path = SQL_ROOT) -> list[str]:
    """Apply schema files, then rebuild every view. Returns paths relative to sql_root."""
    applied = []
    with conn.transaction():
        for path in sorted((sql_root / "schema").glob("*.sql")):
            conn.execute(path.read_text())
            applied.append(path.relative_to(sql_root).as_posix())
        # Views are rebuilt from scratch so a changed column list never blocks
        # CREATE OR REPLACE VIEW.
        conn.execute("DROP SCHEMA IF EXISTS mart CASCADE")
        conn.execute("CREATE SCHEMA mart")
        for path in sorted((sql_root / "views").glob("*.sql")):
            conn.execute(path.read_text())
            applied.append(path.relative_to(sql_root).as_posix())
    return applied
```

```sql
-- created_date, closed_date and last_modified_date are Socrata "floating" timestamps:
-- they carry no time zone and are America/Chicago local time.

    sr_number           text PRIMARY KEY,
    sr_type             text,
    sr_short_code       text,
    owner_department    text,
    status              text,
    origin              text,
    created_date        timestamp NOT NULL,
    closed_date         timestamp,
    last_modified_date  timestamp,
    duplicate           boolean,
    legacy_record       boolean,
    parent_sr_number    text,
    ward                integer,
    community_area      integer,
    latitude            double precision,
    longitude           double precision,
    source_row_id       text NOT NULL,
    source_updated_at   timestamptz NOT NULL,
    loaded_at           timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS service_requests_created_date_idx
    ON raw.service_requests (created_date);
CREATE INDEX IF NOT EXISTS service_requests_sr_type_idx
    ON raw.service_requests (sr_type);
CREATE INDEX IF NOT EXISTS service_requests_community_area_idx
    ON raw.service_requests (community_area);
CREATE INDEX IF NOT EXISTS service_requests_status_idx
    ON raw.service_requests (status);
```

```sql
-- The incremental-load watermark: the last (:updated_at, :id) pair committed to
-- raw.service_requests. Both are kept as the exact text the Socrata API returned so they

CREATE TABLE IF NOT EXISTS meta.load_state (
```

`pipeline/transform.py`:

```python
"""Turn one Socrata API row into a dict keyed by raw.service_requests column names."""

from datetime import datetime
from typing import Any

COLUMNS = (
    "sr_number", "sr_type", "sr_short_code", "owner_department", "status", "origin",
    "created_date", "closed_date", "last_modified_date", "duplicate", "legacy_record",
    "parent_sr_number", "ward", "community_area", "latitude", "longitude",
    "source_row_id", "source_updated_at",
)

_TEXT = (
    "sr_number", "sr_type", "sr_short_code", "owner_department", "status", "origin",
    "parent_sr_number",
)
_TIMESTAMPS = ("created_date", "closed_date", "last_modified_date")
_BOOLS = ("duplicate", "legacy_record")
_INTS = ("ward", "community_area")
_FLOATS = ("latitude", "longitude")


def _present(value: Any) -> bool:
    return value is not None and value != ""


def _bool(value: Any) -> bool | None:
    if isinstance(value, bool) or value is None:
        return value
    return str(value).lower() == "true"


def parse_record(row: dict[str, Any]) -> dict[str, Any]:
    """Type one API row. Missing or empty fields become None."""
    record: dict[str, Any] = {}
    for name in _TEXT:
        record[name] = row[name] if _present(row.get(name)) else None
    for name in _TIMESTAMPS:
        value = row.get(name)
        # Floating timestamps like "2026-11-01T07:57:20.000" parse to naive datetimes.
        record[name] = datetime.fromisoformat(value) if _present(value) else None
    for name in _BOOLS:
        record[name] = _bool(row.get(name))
    for name in _INTS:
        value = row.get(name)
        record[name] = int(float(value)) if _present(value) else None
    for name in _FLOATS:
        value = row.get(name)
        record[name] = float(value) if _present(value) else None
    record["source_row_id"] = row[":id"]
    record["source_updated_at"] = datetime.fromisoformat(row[":updated_at"])
    return record
```

Note: `_bool("")` would return `False`; empty-string booleans have not been seen from the API, and `duplicate` absent returns `None`, which the views treat as not-a-duplicate.

```python
"""Page through the Socrata API using keyset pagination on (:updated_at, :id).

Keyset paging (rather than $offset) means a row that changes mid-run moves to the end of
the ordering instead of shifting every later row and causing one to be skipped.
"""

import time
from collections.abc import Callable, Iterator
from dataclasses import dataclass
from typing import Any

import requests

from pipeline.config import AREAS_URL, DATASET_URL, PAGE_SIZE, SEED_DATE

MAX_ATTEMPTS = 5
REQUEST_TIMEOUT = 120  # seconds; a 50,000-row page can be slow


class ExtractError(RuntimeError):
    """The API rejected a request, or kept failing after every retry."""


@dataclass(frozen=True)
class Watermark:
    updated_at: str
    row_id: str


def watermark_from_row(row: dict[str, Any]) -> Watermark:
    return Watermark(updated_at=row[":updated_at"], row_id=row[":id"])


def build_params(watermark: Watermark | None, seed_date: str, limit: int) -> dict[str, str]:
    where = f"created_date >= '{seed_date}'"
    if watermark is not None:
        where += (
            f" AND (:updated_at > '{watermark.updated_at}'"
            f" OR (:updated_at = '{watermark.updated_at}' AND :id > '{watermark.row_id}'))"
        )
    return {
        "$select": ":id,:updated_at,*",
        "$where": where,
        "$order": ":updated_at,:id",
        "$limit": str(limit),
    }


def fetch_page(
    session: requests.Session,
    url: str,
    params: dict[str, str],
    *,
    app_token: str | None = None,
    sleep: Callable[[float], None] = time.sleep,
) -> list[dict[str, Any]]:
    """GET one page. Retries 429, 5xx and network errors with backoff of 1, 2, 4, 8 seconds."""
    headers = {"X-App-Token": app_token} if app_token else {}
    problem = ""
    for attempt in range(1, MAX_ATTEMPTS + 1):
        try:
            response = session.get(url, params=params, headers=headers, timeout=REQUEST_TIMEOUT)
        except (requests.ConnectionError, requests.Timeout) as exc:
            problem = f"{type(exc).__name__}: {exc}"
        else:
            if response.status_code == 200:
                return response.json()
            if response.status_code != 429 and response.status_code < 500:
                raise ExtractError(
                    f"HTTP {response.status_code} from {url}: {response.text[:500]}"
                )
            problem = f"HTTP {response.status_code}"
        if attempt < MAX_ATTEMPTS:
            sleep(2 ** (attempt - 1))
    raise ExtractError(f"gave up after {MAX_ATTEMPTS} attempts on {url}: {problem}")


def iter_pages(
    session: requests.Session,
    watermark: Watermark | None,
    *,
    seed_date: str = SEED_DATE,
    page_size: int = PAGE_SIZE,
    url: str = DATASET_URL,
    app_token: str | None = None,
    sleep: Callable[[float], None] = time.sleep,
) -> Iterator[list[dict[str, Any]]]:
    """Yield pages of rows changed after the watermark, oldest change first."""
    while True:
        params = build_params(watermark, seed_date, page_size)
        rows = fetch_page(session, url, params, app_token=app_token, sleep=sleep)
        if not rows:
            return
        yield rows
        if len(rows) < page_size:
            return
        watermark = watermark_from_row(rows[-1])


def fetch_community_areas(
    session: requests.Session,
    *,
    url: str = AREAS_URL,
    app_token: str | None = None,
    sleep: Callable[[float], None] = time.sleep,
) -> list[dict[str, Any]]:
    """Fetch the 77 community areas as rows with keys area_numbe and community."""
    params = {"$select": "area_numbe,community", "$limit": "100"}
    return fetch_page(session, url, params, app_token=app_token, sleep=sleep)
```

```python
"""Write parsed 311 records and the incremental-load watermark to Postgres."""

import time
from collections.abc import Callable
from typing import Any

import psycopg
import requests

from pipeline.config import DATASET_URL, PAGE_SIZE, SEED_DATE
from pipeline.extract import Watermark, iter_pages, watermark_from_row
from pipeline.transform import COLUMNS, parse_record

_UPSERT = (
    f"INSERT INTO raw.service_requests ({', '.join(COLUMNS)}) "
    f"VALUES ({', '.join(f'%({c})s' for c in COLUMNS)}) "
    "ON CONFLICT (sr_number) DO UPDATE SET "
    + ", ".join(f"{c} = EXCLUDED.{c}" for c in COLUMNS if c != "sr_number")
    + ", loaded_at = now()"
)


def upsert_records(conn: psycopg.Connection, records: list[dict[str, Any]]) -> None:
    with conn.cursor() as cur:
        cur.executemany(_UPSERT, records)


def get_watermark(conn: psycopg.Connection) -> Watermark | None:
    row = conn.execute("SELECT updated_at, row_id FROM meta.load_state WHERE id = 1").fetchone()
    return Watermark(*row) if row else None


def set_watermark(conn: psycopg.Connection, watermark: Watermark) -> None:
    conn.execute(
        "INSERT INTO meta.load_state (id, updated_at, row_id) VALUES (1, %s, %s) "
        "ON CONFLICT (id) DO UPDATE SET updated_at = EXCLUDED.updated_at, "
        "row_id = EXCLUDED.row_id, saved_at = now()",
        (watermark.updated_at, watermark.row_id),
    )


def load_page(conn: psycopg.Connection, rows: list[dict[str, Any]]) -> Watermark:
    """Upsert one API page and advance the watermark in a single transaction.

    If anything fails, neither the rows nor the watermark change, so the next run
    refetches this page.
    """
    watermark = watermark_from_row(rows[-1])
    with conn.transaction():
        upsert_records(conn, [parse_record(r) for r in rows])
        set_watermark(conn, watermark)
    return watermark


def run_load(
    conn: psycopg.Connection,
    session: requests.Session,
    *,
    app_token: str | None = None,
    url: str = DATASET_URL,
    seed_date: str = SEED_DATE,
    page_size: int = PAGE_SIZE,
    sleep: Callable[[float], None] = time.sleep,
    log: Callable[[str], None] = print,
) -> int:
    """Load every row changed since the saved watermark. Returns the number of rows loaded."""
    total = 0
    pages = iter_pages(
        session,
        get_watermark(conn),
        seed_date=seed_date,
        page_size=page_size,
        url=url,
        app_token=app_token,
        sleep=sleep,
    )
    for rows in pages:
        watermark = load_page(conn, rows)
        total += len(rows)
        log(f"loaded {total:,} rows (watermark {watermark.updated_at})")
    return total


def load_community_areas(conn: psycopg.Connection, rows: list[dict[str, Any]]) -> int:
    with conn.transaction(), conn.cursor() as cur:
        cur.executemany(
            "INSERT INTO ref.community_areas (area_number, name) VALUES (%s, %s) "
            "ON CONFLICT (area_number) DO UPDATE SET name = EXCLUDED.name",
            [(int(r["area_numbe"]), r["community"]) for r in rows],
        )
    return len(rows)
```

```sql
-- The requests every metric is built from. Removes:
--   * duplicates: the city flags a repeat report of the same problem with duplicate = true
--   * 311 INFORMATION ONLY CALL: closed within seconds, would pull every median toward zero
--   * completed requests whose closed_date is missing or earlier than created_date
--     (listed in mart.v_data_issues instead of disappearing silently)
-- response_hours is set only for completed requests.
CREATE OR REPLACE VIEW mart.v_requests_clean AS
SELECT
    sr_number,
    sr_type,
    owner_department,
    status,
    origin,
    created_date,
    closed_date,
    community_area,
    ward,
    latitude,
    longitude,
    CASE
        WHEN status = 'Completed'
            THEN EXTRACT(EPOCH FROM closed_date - created_date)::double precision / 3600
    END AS response_hours
FROM raw.service_requests
WHERE duplicate IS NOT TRUE
  AND sr_type IS DISTINCT FROM '311 INFORMATION ONLY CALL'
  AND (
      status IS DISTINCT FROM 'Completed'
      OR (closed_date IS NOT NULL AND closed_date >= created_date)
  );
```

`sql/views/020_v_data_issues.sql`:

```sql
-- Completed requests whose timestamps cannot produce a response time.
-- Their count is itself a data-quality finding.
CREATE OR REPLACE VIEW mart.v_data_issues AS
SELECT
    sr_number,
    sr_type,
    status,
    created_date,
    closed_date,
    CASE
        WHEN closed_date IS NULL THEN 'completed_without_closed_date'
        ELSE 'closed_before_created'
    END AS reason
FROM raw.service_requests
WHERE status = 'Completed'
  AND (closed_date IS NULL OR closed_date < created_date);
```

```sql
-- Open requests by age. Age is measured from the latest created_date in the data (the
-- snapshot time) rather than now(), so results do not drift between loads.
CREATE OR REPLACE VIEW mart.v_backlog AS
WITH as_of AS (
    SELECT max(created_date) AS ts FROM raw.service_requests
),
open_requests AS (
    SELECT c.sr_type, a.ts - c.created_date AS age
    FROM mart.v_requests_clean AS c
    CROSS JOIN as_of AS a
    WHERE c.status = 'Open'
)
SELECT
    sr_type,
    CASE
        WHEN age < interval '1 day' THEN '1: <1 day'
        WHEN age < interval '7 days' THEN '2: 1-7 days'
        WHEN age < interval '30 days' THEN '3: 7-30 days'
        WHEN age < interval '90 days' THEN '4: 30-90 days'
        ELSE '5: 90+ days'
    END AS age_bucket,
    count(*) AS open_requests
FROM open_requests
GROUP BY 1, 2;
```

```python
"""Write the aggregated mart views to CSV files for Tableau Public, which cannot read
Postgres directly. v_requests_clean is not exported: it has millions of rows."""

from pathlib import Path

import psycopg

EXPORT_VIEWS = (
    "v_city_month",
    "v_type_month",
    "v_area_type",
    "v_backlog",
    "v_origin",
    "v_area_centroid",
)


def export_views(conn: psycopg.Connection, out_dir: Path) -> dict[str, int]:
    """Write one CSV per view, header included. Returns data-row counts by view."""
    out_dir.mkdir(parents=True, exist_ok=True)
    counts = {}
    for view in EXPORT_VIEWS:
        copy_sql = (
            f"COPY (SELECT * FROM mart.{view} ORDER BY 1, 2) "
            "TO STDOUT WITH (FORMAT csv, HEADER true)"
        )
        with open(out_dir / f"{view}.csv", "wb") as f, conn.cursor() as cur:
            with cur.copy(copy_sql) as copy:
                for chunk in copy:
                    f.write(chunk)
        counts[view] = conn.execute(f"SELECT count(*) FROM mart.{view}").fetchone()[0]
    return counts
```

`sql/analysis/01_long_tail_types.sql`:

```sql
-- Which services help most people quickly but leave some waiting far longer?
-- Long tail = the gap between the 90th percentile and the median response time.
-- Only types with at least 1,000 completed requests, so the percentiles are stable.
WITH per_type AS (
    SELECT
        sr_type,
        count(response_hours) AS completed,
        percentile_cont(0.5) WITHIN GROUP (ORDER BY response_hours) AS median_hours,
        percentile_cont(0.9) WITHIN GROUP (ORDER BY response_hours) AS p90_hours
    FROM mart.v_requests_clean
    GROUP BY sr_type
    HAVING count(response_hours) >= 1000
)
SELECT
    sr_type,
    completed,
    round(median_hours::numeric, 1) AS median_hours,
    round(p90_hours::numeric, 1) AS p90_hours,
    round((p90_hours / NULLIF(median_hours, 0))::numeric, 1) AS p90_to_median
FROM per_type
ORDER BY p90_hours - median_hours DESC
LIMIT 15;
```

`sql/analysis/02_area_gap_within_type.sql`:

```sql
-- For the 10 busiest request types: does where you live change how fast the city responds?
-- Compares the fastest and slowest community area for each type. Areas with fewer than 50
-- completed requests of that type are left out so one odd case cannot set the median.
WITH top_types AS (
    SELECT sr_type
    FROM mart.v_requests_clean
    GROUP BY sr_type
    ORDER BY count(*) DESC
    LIMIT 10
),
ranked AS (
    SELECT
        a.sr_type,
        a.area_name,
        a.median_hours,
        row_number() OVER (PARTITION BY a.sr_type ORDER BY a.median_hours ASC) AS fastest_rank,
        row_number() OVER (PARTITION BY a.sr_type ORDER BY a.median_hours DESC) AS slowest_rank
    FROM mart.v_area_type AS a
    JOIN top_types AS t USING (sr_type)
    WHERE a.completed >= 50
)
SELECT
    f.sr_type,
    f.area_name AS fastest_area,
    round(f.median_hours::numeric, 1) AS fastest_median_hours,
    s.area_name AS slowest_area,
    round(s.median_hours::numeric, 1) AS slowest_median_hours,
    round((s.median_hours / NULLIF(f.median_hours, 0))::numeric, 1) AS gap_ratio
FROM ranked AS f
JOIN ranked AS s ON s.sr_type = f.sr_type AND s.slowest_rank = 1
WHERE f.fastest_rank = 1
ORDER BY gap_ratio DESC NULLS LAST;
```

`sql/analysis/03_yoy_top_types.sql`:

```sql
-- Is the city getting faster or slower? Median response hours by year for the 10 busiest
-- request types. 2026 is a partial year, so seasonal types (snow, tree trimming) can skew it.
WITH top_types AS (
    SELECT sr_type
    FROM mart.v_requests_clean
    GROUP BY sr_type
    ORDER BY count(*) DESC
    LIMIT 10
)
SELECT
    c.sr_type,
    count(*) AS requests,
    round((percentile_cont(0.5) WITHIN GROUP (ORDER BY c.response_hours)
        FILTER (WHERE extract(year FROM c.created_date) = 2023))::numeric, 1) AS median_2023,
    round((percentile_cont(0.5) WITHIN GROUP (ORDER BY c.response_hours)
        FILTER (WHERE extract(year FROM c.created_date) = 2024))::numeric, 1) AS median_2024,
    round((percentile_cont(0.5) WITHIN GROUP (ORDER BY c.response_hours)
        FILTER (WHERE extract(year FROM c.created_date) = 2025))::numeric, 1) AS median_2025,
    round((percentile_cont(0.5) WITHIN GROUP (ORDER BY c.response_hours)
        FILTER (WHERE extract(year FROM c.created_date) = 2026))::numeric, 1) AS median_2026
FROM mart.v_requests_clean AS c
JOIN top_types AS t USING (sr_type)
GROUP BY c.sr_type
ORDER BY requests DESC;
```

```ts
  const first = await soql(request, { ...base, $where: ONE_DAY, $limit: '5' });
```

````markdown
When Chicagoans call 311 about a pothole, graffiti, or a broken streetlight, how long do they

311 service request since 2023 from the [Chicago Data Portal](https://data.cityofchicago.org/d/v6vf-nfxy)

dashboards. It is also a test-automation project: the pipeline and SQL are covered by pytest,
and a Playwright suite checks the live portal every night for changes that would break the load.

## Findings

See [docs/findings.md](docs/findings.md). Each finding links to the SQL that produced it in
[sql/analysis/](sql/analysis/).

## Dashboards

- Tableau Public: see [dashboards/tableau/](dashboards/tableau/)
- Power BI: see [dashboards/powerbi/](dashboards/powerbi/)

## How it works

```
Socrata API (v6vf-nfxy)
  -> chi311 load      pages through changes since the last run, keyset on (:updated_at, :id)
  -> raw.service_requests      upsert by sr_number; watermark saved in the same transaction
  -> mart.* views              cleaning, monthly / area / channel / backlog aggregates
  -> chi311 export    CSVs for Tableau Public
     Power BI         imports the mart views directly
```

| Path | What it holds |
|---|---|
| `pipeline/` | Python loader: extract, transform, load, export, CLI |
| `sql/schema/` | tables: `raw.service_requests`, `meta.load_state`, `ref.community_areas` |
| `sql/views/` | analysis views in schema `mart`, shared by both dashboards |
| `sql/analysis/` | one query per finding |
| `tests/` | pytest unit and integration tests |
| `e2e/` | Playwright TypeScript tests against the live portal |

### Cleaning rules

- Duplicates (`duplicate = true`) are dropped.
- `311 INFORMATION ONLY CALL` is dropped: these close within seconds and would drag medians toward zero.
- Response time is `closed_date - created_date`, for completed requests only.
- Completed requests with no `closed_date`, or one before `created_date`, are listed in `mart.v_data_issues` instead of being dropped silently.
- Areas are compared by community area (77, stable for decades), not by ward: ward boundaries were redrawn in May 2023, so 2023 ward values mix two maps.

## What the tests catch

**pytest** (the code in this repo; coverage is reported to Codecov):

- API paging that skips or repeats rows, and wrong retry behavior on rate limits and server errors.
- Type mistakes when parsing API rows: time zones, booleans, numbers sent as strings, missing fields.
- A re-run that duplicates rows, an update that fails to overwrite, and a crash that advances the watermark past rows that were never saved.
- Wrong numbers in any view. Every view is checked against values worked out by hand from a 13-row fixture that includes a duplicate, an info call, an open request, a canceled request, and two broken timestamps.
- Exports with missing columns or rows.

**Playwright** (the live Chicago Data Portal, nightly):

- A renamed, removed, or retyped field the loader depends on.
- A change in timestamp format, `$where` filtering, `$limit`, or keyset ordering that would make an incremental load skip or repeat rows.
- Malformed queries no longer failing loudly.
- The dataset page, its column list, CSV export, or catalog search breaking.

A nightly E2E failure with no code change means the portal changed. The HTML report and traces
are attached to the workflow run.

## Known limitations

- The portal sometimes re-publishes the whole dataset, which resets `:updated_at` on every row. The next `chi311 load` then refetches everything. That is slow but correct, because the load is idempotent.
- Timestamps are Chicago local time with no time zone, as published.
- Some request types (for example aircraft noise complaints) close almost instantly by design. Compare response times within a type, not across types.
````
